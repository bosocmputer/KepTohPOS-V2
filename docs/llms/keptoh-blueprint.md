# KepToh POS ("เก็บโต๊ะ") — Blueprint v0.1

> เอกสารนี้ให้ AI ทุกตัวในโปรเจกต์อ่านก่อนเขียนโค้ด สถานะ: **Prototype / รอยืนยันกฎธุรกิจ**

## 1. เป้าหมายผลิตภัณฑ์
- POS สำหรับ **ร้านหมูกระทะบุฟเฟต์ในไทย** โดยเฉพาะ ขายแบบรายเดือนราคาไม่แพง (ตั้งใจให้ดูเป็นระบบเล็ก ไม่ใช่ POS ร้านอาหารเต็มรูป)
- สิ่งที่ร้านต้องการรู้: **"วันนี้ขายบุฟเฟต์ได้กำไรหรือขาดทุน"**
- อนาคต: เปิดโหมด "ร้านอาหารทั่วไป (ไม่บุฟเฟต์)" เป็นแพ็กเกจแยก — ออกแบบ data model ให้รองรับ แต่ **ยังไม่สร้าง**

## 2. บริบทการใช้งานจริง (ลูกค้ารายแรก)
- iPad/แท็บเล็ต **1 เครื่อง** ที่แคชเชียร์ ไม่มีคอม ไม่มีมือถือพนักงาน
- **จ่ายก่อนกิน** · แยกราคา ผู้ใหญ่ / เด็ก (+ เด็กเล็กทานฟรี)
- ไม่จับเวลา แต่มีตัวเลือกจับเวลาก็ดี
- ขายเสริม: น้ำ น้ำแข็ง น้ำอัดลม เบียร์ (สต็อกแยกจากวัตถุดิบบุฟเฟต์)
- ซื้อของสดทุกวันจากหลายที่ (ตลาดสด แม็คโคร) วัตถุดิบหลัก 10–20 รายการ
- ปิดร้าน → พนักงานชั่ง/นับของเหลือ → ระบบหักสต็อก + คิดต้นทุนเอง (ไม่ต้องเบิกทีละรายการ)
- เครื่องพิมพ์สลิป **Bluetooth** (เฟสถัดไป)
- ความเสี่ยงหลัก: **ร้านขี้เกียจคีย์ข้อมูล** → ทุกหน้าจอต้องคีย์น้อยที่สุด (เช่น ปุ่ม "ใช้รายการเดิมจากครั้งก่อน")

## 3. สูตรหลัก (สถานะ)
| สูตร | สถานะ |
|---|---|
| วัตถุดิบที่ใช้ = ยกมา + ซื้อเข้า − เหลือจริง | ✅ ตามที่คุยกับทีม |
| มูลค่าต่อหน่วย = ต้นทุนเฉลี่ยถ่วงน้ำหนัก | ⚠️ สมมติใน prototype — **รอยืนยัน** (ทางเลือก: ราคาซื้อล่าสุด / FIFO) |
| กำไรขั้นต้น = ยอดขายก่อน VAT − ต้นทุนวัตถุดิบที่ใช้ − ต้นทุนเครื่องดื่ม | ⚠️ ยังไม่รวมแก๊ส/ค่าแรง/ค่าเช่า — **รอยืนยัน** |
| ต้นทุนต่อหัว = ต้นทุนวัตถุดิบ ÷ (ผู้ใหญ่ + เด็ก) | ⚠️ เด็กนับเป็น 1 หัว — **รอยืนยัน** |
| VAT: none / included 7% / excluded 7% | ✅ เป็นตัวเลือกในตั้งค่า (ค่าเริ่มต้น none) |
| การปัดเศษสตางค์, ค่าปรับอาหารเหลือ, service charge | ❓ **ยังไม่มีข้อมูล** |

## 4. โมดูล (Prototype ครบแล้ว)
1. **โต๊ะ/ขาย** — เปิดโต๊ะ → แพ็กเกจ + จำนวนคน + ขายเสริม → ชำระ (เงินสด/QR พร้อมเพย์/โอน) → ใบเสร็จ → สั่งเพิ่ม (บิลแยก) → เก็บโต๊ะ · จับเวลาตามแพ็กเกจ
2. **บิล** — ดูย้อนหลังรายวัน, ยกเลิกบิล (ผู้จัดการขึ้นไป + เหตุผล)
3. **สต็อก** — นับของเหลือ/ปิดวัน, รับของเข้า (คัดลอกบิลเดิม), คงเหลือ + แนะนำสั่งซื้อ (ระดับที่ควรมี − คงเหลือ)
4. **กะ** — เปิดกะ (เงินทอนตั้งต้น), ปิดกะ (นับเงินสด vs ที่ควรมี)
5. **ภาพรวม** — กำไร, ต้นทุน/หัว, Food cost %, กราฟกำไรรายวัน, ต้นทุนแยกวัตถุดิบ, ขายเสริม
6. **รายงาน** — ตารางรายวันต่อเดือน
7. **ตั้งค่า (CRUD)** — ร้าน/ใบเสร็จ, แพ็กเกจ, ขายเสริม, วัตถุดิบ, แหล่งซื้อ, โต๊ะ, พนักงาน+สิทธิ์ (PIN), ช่องทางชำระ

สิทธิ์: แคชเชียร์ = โต๊ะ บิล สต็อก กะ · ผู้จัดการ = + ภาพรวม รายงาน ตั้งค่า ยกเลิกบิล · เจ้าของ = ทุกอย่าง

## 5. Tech (เสนอ — รอยืนยัน)
- **Prototype ตอนนี้:** `prototype/index.html` ไฟล์เดียว (Preact + htm จาก CDN, ข้อมูลใน localStorage) — ใช้ให้ร้านลองกด ไม่ใช่โค้ดจริง
- **แอปจริง:** Flutter (iPad + Android, พิมพ์ Bluetooth ESC/POS ได้, SQLite ในเครื่อง → ขายได้ตอนเน็ตหลุด)
- **Cloud (ตอนขายรายเดือน):** Go + PostgreSQL — login, backup, multi-tenant, ดูรายงานจากมือถือเจ้าของ
- **Design:** Figma (Makaryo POS community kit) → ต้องเชื่อม Figma MCP ใน session ใหม่ แล้วแตก components กลาง

## 7. Mock data (อ้างอิงการค้นข้อมูล พ.ย. 2569 — ใช้ทดสอบเท่านั้น)
- บุฟเฟต์ 199 / เด็ก 99 (สูง 100–130 ซม.), หมู+ทะเล 279 / 139 · ต่ำกว่า 100 ซม. ฟรี
- หมูสามชั้น ~175–220 ฿/กก., สันนอก ~145–150 ฿/กก. (มี.ค.–เม.ย. 69; ไม่พบราคา ต.ค. 69)
- เป้า Food cost ร้านหมูกระทะ 30–35%
- ปริมาณกิน/หัว (กรัม) **ไม่มีข้อมูลจริง** — ค่าใน seed เป็นสมมติเพื่อจำลองเท่านั้น

## 8. ยังไม่ทำ (YAGNI)
พิมพ์ Bluetooth · LINE OA / AI อ่านบิล · ลูกค้าสั่งเองผ่าน QR · หลายสาขา · สมาชิก/แต้ม · โหมดร้านอาหารทั่วไป

## 9. คำถามค้างถามร้าน
1. ราคาแพ็กเกจจริง + เกณฑ์เด็ก 2. วิธีคิดต้นทุน (เฉลี่ย/ล่าสุด) 3. รวมค่าใช้จ่ายอื่นในกำไรไหม 4. จด VAT ไหม / ปัดเศษ / ค่าปรับอาหารเหลือ 5. ช่องทางชำระที่ใช้จริง 6. รุ่น iPad/แท็บเล็ต และเครื่องพิมพ์
