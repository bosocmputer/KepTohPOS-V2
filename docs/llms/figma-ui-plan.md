## 0. ขอบเขต
- ยังเป็น **prototype** (Preact + htm จาก CDN, เก็บข้อมูลใน localStorage) ยังไม่ต่อ database
- เปิดได้ด้วยการดับเบิลคลิก `prototype/index.html` (file://) ต้องใช้งานได้เสมอ
- ไม่เพิ่ม dependency ใหม่ · เปลี่ยน UI ตาม Figma + เปลี่ยน logic เท่าที่ระบุในข้อ 3 เท่านั้น
- เป้าหมาย: **กดเล่นได้ครบ flow + ใช้ mock JSON + หน้าตาใกล้เคียง Figma ที่สุด** (ไม่ต้อง 100%) เพื่อส่งให้ทีม/ร้านลอง
- จุดเน้นของ product: **กำไรขาดทุน / ต้นทุน** และ **บันทึกของให้เร็วที่สุด** (ไม่ให้ร้านเสียเวลาคีย์)
- เรื่อง stack ของตัวจริง (Flutter web / cloud) **พักไว้ก่อน** ไม่อยู่ในขอบเขตนี้

## 0.1 หลักการ components กลาง (บังคับ)
- **แก้ต่อจากโค้ดเดิม ห้ามเขียนใหม่ทั้งไฟล์** · ทุกหน้าประกอบจาก components ในตารางนี้
- ต้องการหน้าตาใหม่ → เพิ่ม prop/variant ให้ component เดิม ห้ามก๊อปไปแก้เป็นอีกตัว
- หน้าที่ Figma ไม่มี → ประกอบจาก components ชุดนี้ให้ style เข้าชุด
- ฟังก์ชันธุรกิจและ util ใช้ตัวเดิม (`calcOrder`, `makeBill`, ledger, `fmt`/`baht`/วันที่) ห้ามเขียนซ้ำ
- component ใหม่วางไว้ในส่วน `shared components` ของไฟล์ ไม่ซ่อนไว้ในหน้าใดหน้าหนึ่ง

## 2. Theme (เปลี่ยนที่เดียว เปลี่ยนทั้งระบบ)
- ไฟล์ `prototype/theme.css` แบ่ง 2 ชั้น
  - **ชั้นสีดิบ:** `figma` (Orange 500 `#FE4E10`, 600 `#EF3408`, 100 `#FFE6D4`, 50 `#FFF4ED`, Neutral 50–950, Green `#16A34A`, Red `#DC2626`, Dark `#141B34`) และ `team` (`#FF7A00`, `#20242C`, `#F4F4F5`, `#172033`, `#16A36A`, `#E5484D`)

- โหมดมืด: `data-theme="light|dark"` + ตามเครื่อง override เฉพาะชั้นความหมาย ต้องใช้ได้ทั้ง 2 ธีม

- หน้าตั้งค่า: ตัวสลับธีม (Figma/ทีม) + โหมด (สว่าง/มืด/ตามเครื่อง)

## 3. ข้อมูลและกฎธุรกิจ
### Mock data (JSON)
- `prototype/data/mock-data.js` = `window.KEPTOH_MOCK = { ...JSON ล้วน... }` (ไฟล์ .json อ่านผ่าน file:// ไม่ได้)
- ข้อมูลหลักอยู่ในไฟล์นี้: ร้าน, หมวด, สินค้า (แพ็กเกจบุฟเฟต์เป็นหมวดหนึ่ง), โต๊ะ, พนักงาน, วัตถุดิบ, แหล่งซื้อ, ช่องทางจ่าย
- ยอดขายย้อนหลัง 30 วันยังสร้างด้วยโค้ด (วันที่ต้องอิงวันนี้)
- หน้าตั้งค่า: ปุ่ม **ส่งออก / นำเข้า JSON** + รีเซ็ตเป็นข้อมูลตัวอย่าง

### จ่ายก่อนกิน / กินก่อนจ่าย (ยืนยันกับเจ้าของแล้ว)
- ร้านตั้งค่าเริ่มต้น `shop.payTiming = 'before' | 'after'` และ**เปลี่ยนรายโต๊ะได้ตอนเปิดโต๊ะ**
- แยก **ออเดอร์ของโต๊ะ** (รายการ + จำนวนคน ทุกรอบที่สั่ง) ออกจาก **บิล** (สร้างตอนรับเงินเท่านั้น)
  - จ่ายก่อน: ปุ่ม "รับเงิน" ทุกรอบ → บิลแยกรอบละใบ (พฤติกรรมเดิม)
  - กินก่อน: "ส่งออเดอร์" สะสมรายการ → "เช็กบิล" → บิลเดียว
- การ์ดโต๊ะมีสถานะ "รอชำระ" + ยอดค้าง · เก็บโต๊ะได้เมื่อชำระครบ · ปิดกะต้องเตือนถ้ามีโต๊ะค้างชำระ
- ยอดขายนับตาม **วันที่รับเงิน**
- ลบ/ลดรายการที่ส่งแล้วแต่ยังไม่จ่าย: **ผู้จัดการขึ้นไป + ใส่เหตุผล** (เก็บประวัติไว้)
- ไม่ทำรอบนี้: แยกบิล/หารจ่าย, พิมพ์ใบแจ้งยอด, ส่งออเดอร์เข้าครัว, โหมดร้านอาหาร (แต่โครงสินค้า+หมวดต้องรองรับ)

### 5.1 บันทึกของ — เป้า: **ครบทั้งวันไม่เกิน 3 นาที** (ตัวเลขเสนอเอง ต้องลองกับร้านจริง)
- **รับของเข้า:** ปุ่ม "เหมือนครั้งก่อน" แตะเดียวได้รายการเดิมทั้งหมด (แยกตามแหล่งซื้อ) แล้วแก้เฉพาะตัวที่ราคา/จำนวนเปลี่ยน
- **นับของเหลือ:** เรียงตามตำแหน่งเก็บจริง (`ingredient.location`: ตู้เย็น → ตู้แช่แข็ง → ชั้นแห้ง) · `NumPad` ใหญ่ · Enter ไปรายการถัดไปทันที · แสดงค่าที่นับครั้งก่อนเป็นตัวช่วย
- **โหมดนับละเอียด/หยาบ:** `ingredient.countFreq = 'daily' | 'weekly'` · วันปกตินับเฉพาะ daily (เช่น หมู ทะเล) ตัว weekly ใช้ค่าคาดการณ์จากการใช้เฉลี่ย และขึ้นรายการให้นับในวันที่กำหนด
- **ค่าใช้จ่ายรายวัน** (แก๊ส น้ำแข็ง ถ่าน) บันทึกแบบเดียวกับรับของ แต่หมวด "ค่าใช้จ่าย" ไม่เข้าสต็อก
- **ไม่ทำตอนนี้:** ถ่ายรูปบิลให้ AI อ่าน, LINE OA

### 5.2 กำไรขาดทุน — ค่าเริ่มต้นชั่วคราว (ผู้ใช้ให้ตัดสินใจเองในบริบทร้านไทย · ปรับได้ในตั้งค่า · ต้องยืนยันกับร้านภายหลัง)
| เรื่อง | ค่าเริ่มต้น | ตัวเลือกในตั้งค่า | เหตุผล |
|---|---|---|---|
| มูลค่าวัตถุดิบ | ต้นทุนเฉลี่ยถ่วงน้ำหนัก | เฉลี่ย / ราคาซื้อล่าสุด | ง่าย นิ่ง ไม่ต้องติดตามล็อต (FIFO ไม่ทำ) |
| กำไรที่แสดง | 2 ชั้น: **กำไรขั้นต้น** (ขาย − วัตถุดิบ − เครื่องดื่ม) และ **กำไรสุทธิโดยประมาณ** (− ค่าใช้จ่ายรายวัน − ค่าคงที่รายเดือนเฉลี่ยต่อวันที่เปิดร้าน) | เปิด/ปิดกำไรสุทธิ | ร้านอยากรู้ "วันนี้ได้หรือเสีย" จริง ไม่ใช่แค่ food cost |
| ค่าคงที่รายเดือน | รายการ ค่าเช่า / ค่าแรง / ค่าน้ำไฟ (กรอกต่อเดือน) | CRUD | กรอกเดือนละครั้ง ไม่เพิ่มงานรายวัน |
| ต้นทุนต่อหัว | เด็กนับ **0.5 หัว** · เด็กเล็กฟรี 0 | ค่าน้ำหนักเด็ก 0–1 | ราคาเด็กประมาณครึ่งหนึ่งของผู้ใหญ่ |
| ค่าปรับอาหารเหลือ | ปิด | เปิด + ราคาต่อหน่วย (ร้านกำหนดเอง) | พบได้ในบุฟเฟต์ไทยแต่ไม่ทุกร้าน · ขายเป็นรายการเสริมในบิล |
| Service charge | 0% | กำหนด % | ร้านหมูกระทะส่วนใหญ่ไม่เก็บ |
| ปัดเศษ | ปัดสตางค์ลงเป็นบาทเต็ม | ไม่ปัด / ปัดลง | ร้านเล็กในไทยแทบไม่ใช้เหรียญสตางค์ |
| VAT | ไม่มี | ไม่มี / รวมใน / แยกนอก 7% | ร้านเล็กมักไม่จด VAT |

- หน้าภาพรวมแสดงป้าย **"ค่าตั้งต้น รอยืนยันกับร้าน"** ข้างตัวเลขกำไร และลิงก์ไปหน้าตั้งค่าเหล่านี้
